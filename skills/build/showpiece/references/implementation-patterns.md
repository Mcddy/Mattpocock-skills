# Implementation patterns for selected expressive work

Read the parts needed for the chosen idea, not every recipe. These preserve technical methods from the supplied showcase bundle. `SKILL.md` governs scope, task/brand precedence, access and authorised tools. Numeric values are adjustable examples, not universal requirements or performance guarantees. No library, sensor, WebGL scene, scroll treatment or camera is compulsory.

## Version and delivery checks

The source bundle contained dated library/version/licensing assertions. They have not been reverified for this package. Before use, inspect official documentation for the exact approved version, delivery surface and capability. A quoted historical version claim is not present compatibility proof. Prefer the existing project stack; pin supported dependencies where appropriate. Age alone (the source suggested a two-week maturity lag) does not establish correctness or safety. A maturity lag may be a project choice alongside actual checks.

- Single-file pages can use HTML, CSS and vanilla JS. When choreography needs GSAP/ScrollTrigger, check official documentation and licensing for the selected version, then pin a tested compatible version through the authorised delivery path. Do not add a library merely to follow a recipe.
- For a selected three.js module build, use an import map with compatible `three` and `three/addons/` paths from the approved local bundle or host. Verify the selected version's module layout rather than assuming a historical release boundary. Consider a smaller WebGL implementation when its capabilities actually suffice.
- Lenis smooth scrolling is allowed on showcase pages with gentle settings: lerp about 0.1, wheelMultiplier 1, syncTouch off so touch stays native, and disabled under reduced motion. Wire it to ScrollTrigger with lenis.on('scroll', ScrollTrigger.update), gsap.ticker.add(t => lenis.raf(t * 1000)) and gsap.ticker.lagSmoothing(0), then test anchors, keyboard paging and find-in-page.
- Set animation start states from JS (gsap.from, or a class added by script), never in CSS, so content stays visible without JS, after anchor jumps and in full-page captures. Call ScrollTrigger.refresh() after fonts and images settle, and give every image a width and height.
- In an existing project, use what's there (Motion, GSAP, React Three Fiber, Framer components) before adding anything.
- Treat CSS scroll-driven animations and the View Transitions API as progressive enhancements behind @supports or feature checks. Check current browser support at build time and keep a JS or static path.
- Check library APIs, shadow options and loading requirements against the exact version's official documentation, not memory. Exercise the intended delivery scheme. If it needs a local server or module bundle, establish that authorised delivery path before promising file-only operation; do not substitute another scheme and claim the requested file workflow passed.

## Asset preparation

Prefer supplied assets, labelled generated material and faithful subject diagrams. The frame counts, sizes and formats below are examples to profile for the actual delivery, not a universal codec benchmark.

- Cut-outs need clean edges at 2x; check hair, mesh and translucent fabric close up.
- Image sequences: the source used 60 to 120 frames at 1x to 1.5x display size (a long edge of about 1920 px for desktop and 1080 px for phones, as separate sets), with the first frame as a poster. Choose frame count, resolution and format from measured loading/decoding cost on the intended surface; WebP, JPEG and AVIF are candidates, not a universal speed ranking.
- 3D models: glTF with Draco or Meshopt compression and baked lighting where possible.
- Sample data has a realistic shape (real-length names, uneven counts, missing values, consistent totals), is labelled as sample and is recomputed after changes.

## Objects that need volume

CSS planes can correctly depict paper and flat surfaces. When the chosen object needs physical thickness and lighting, consider these WebGL techniques rather than pretending a flat plane has volume. Keep the text equivalent and non-WebGL alternative useful.

- PBR materials (MeshStandardMaterial) lit by an environment (RoomEnvironment through PMREMGenerator at modest intensity), one key directional light with soft shadows (shadow map about 1024, radius 4 to 6, small normal bias) and a dim hemisphere fill.
- A transparent canvas with a ShadowMaterial ground, so the page background and theme show through and the shadow lands on the page itself. A thin plinth grounds the object.
- Neutral tone mapping, so colours read from CSS tokens stay true. Re-read the tokens on theme change.
- Real thickness and seams: slabs with a hairline gap, roofs, bevels or edges that catch light. Silhouette and shading carry the believability.
- A 24 to 35 degree field of view from an elevated three-quarter view. Frame automatically: fit the camera to the content's current height and the canvas aspect, and ease towards it when data changes.
- Optional gentle idle sway (under 10 degrees over 12 to 20 s), only when it serves the object and has a visible pause control, rather than an unneeded full spin. Drag adjusts the angle with inertia and limits.
- Labels as HTML projected from 3D anchor points, placed to avoid each other and the object, fading in with their object rather than floating over nothing.
- Hover hits by raycast, mapped back to the data row, with a tooltip placed directly at the pointer and the matching table row highlighted.
- Per-element springs with staggered start times, so changes ripple through the object; frame-rate independent; snapped under reduced motion.
- Render on demand when nothing moves, pause off screen and in hidden tabs, cap pixel ratio at 2, handle context loss, and keep a non-WebGL fallback (a CSS version of the same proportions) plus the text equivalent.

## Fifteen optional recipes

Parameters are starting points. Tune only the selected mechanism in its real context; recipes do not override task/access/brand, and the useful static version exists first.

1. **Masked line reveal.** Split after document.fonts.ready and re-split on resize (GSAP SplitText with mask: 'lines' and autoSplit handles both). Move each line from translateY(100%) to 0 over 700 to 900 ms, expo-out, with a 60 to 90 ms stagger. Give each mask padding-bottom of about 0.15em with an equal negative margin so tight leading doesn't clip descenders. Keep a visually hidden full copy for assistive technology and set the split copy aria-hidden; aria-label is reliable only on headings, links and buttons. Run once per element.
2. **Image unmask.** clip-path from inset(100% 0 0 0) to inset(0) over 1000 to 1200 ms, expo-out, while the inner image scales from 1.15 to 1. For lead images and case-study heroes.
3. **Panel wipe intro.** Five to eight full-height panels scale from 1 to 0 (origin top or bottom), staggered 50 to 80 ms left to right, revealing the already rendered hero in under 1.2 s. Start the headline's line reveal at about 60 per cent of the wipe so it's readable by about 1.4 s. Once per session (wrap storage access in try/catch), skipped under reduced motion, and never a fake 0 to 100 counter.
4. **Hover-reveal index rows.** A bar wipes in with scaleY from the edge the pointer entered, or scaleX from the left, over 350 to 450 ms, and exits towards the side the pointer left. Invert the text with an aria-hidden duplicate clipped by the same transform, so the colour change follows the bar's edge. A preview image cuts in with a clip-path inset in a fixed slot beside the list, aligned to the hovered row, never chasing the pointer over the text; preload previews with img.decode() so the first hover isn't blank. The same reveal runs on :focus-visible. With hover: none, show a static thumbnail and let a tap navigate.
5. **Index to case study.** The clicked preview becomes the case-study hero. Set view-transition-name on that one image at click time; GSAP Flip is the fallback.
6. **Spatial image cluster or helix.** A stage with perspective of 1200 to 2000 px and transform-style preserve-3d, with planes placed by a rule (golden-angle spacing, a helix parametric, project dates along an axis). Derive plane size and radius from the stage width rather than fixed pixels, or a ring that suits 1440 px spills past a phone screen. Ambient rotation of one turn per 30 to 60 s. The pointer tilts the whole scene by at most 8 to 12 degrees with damping, one scene moving like a camera; per-card tilt hovers stay out. Dragging spins it with inertia under a ring cursor reading "Drag"; set touch-action: pan-y on the stage so a sideways drag doesn't block vertical scrolling, and make sure drag is never the only route: arrow keys and the project index reach every plane. Pause when off screen (IntersectionObserver) or when the tab is hidden. Reduced motion gets a still, composed arrangement.
7. **Scroll-scrubbed object.** A sticky stage sized in 100svh inside a section about 150 to 250svh tall maps scroll progress to a frame index drawn on canvas. Preload the poster and every fourth frame first, then fill in, and draw the nearest loaded frame; don't pre-decode every frame to an ImageBitmap. It reverses cleanly when scrolling back. Reduced motion gets three or four labelled key frames as a stepped gallery.
8. **Pinned horizontal strip.** A linear scrub of the track along x while the section is pinned. On focusin, scroll the page to the focused item. Phones get native horizontal scrolling with scroll-snap.
9. **Container metaphor with a hinge.** Two halves with transform-origin at the fold; rotateY (rotateX in portrait) runs from closed to open with scroll progress. The screen content is real DOM, not video, so it stays selectable, linkable and readable. Persist the container across sections or routes as a shared element or with View Transitions. Re-skin standard sections in the object's own vocabulary: Foldfolio shows news as lock-screen notifications and turns contact into an incoming call with "slide to talk". Give a scroll-driven signature a short cue ("Scroll to unfold") until the first scroll.
10. **Participatory particles.** An opt-in button states what the camera is for. MediaPipe Tasks Vision hand landmarks, or plain pointer input, drive displacement of a particle field sampled from the video frame or an image. Mirror the selfie view and flip landmark x (1 - x), or the field reacts on the wrong side. Run detectForVideo once per new frame via requestVideoFrameCallback. Cap particles by device (start around 20,000 on desktop and 5,000 on a phone), stop the tracks on exit and on visibilitychange, and design permission-denied and unsupported states around a pointer-driven fallback. The hand model is fetched from storage.googleapis.com and a sandboxed Artifact may block it or lack camera access; confirm hosting and the camera capability before promising this path.
11. **Blur-through type change.** Outgoing text blurs from 0 to 8 px and fades while incoming text sharpens from 8 px to 0 over 300 to 500 ms. For scene captions and slogans, never body copy.
12. **Marquee.** Duplicate the track, mark the duplicate aria-hidden and inert so its links leave the tab order, and translate at 40 to 80 px per second. Static under reduced motion. One per page at most.
13. **Affordance cursor.** A ring that grows and labels itself (Drag, View, Play) over the elements that need it. The native cursor stays everywhere else, including all text and controls. Off for coarse pointers and under reduced motion.
14. **Grain and screen texture.** Choose the surface by the accepted identity and legibility; flat paper or photography are common examples, and a gradient is not intrinsically forbidden. Static SVG feTurbulence or a small tiled image at 3 to 6 per cent opacity with pointer-events none; animated grain runs at no more than 8 to 12 fps.
15. **Ambient life.** An optional slow loop on the signature (rotation, drift, parallax under 20 px) may support the subject. It needs purpose, a visible pause control and a quiet reduced-motion version; keep reading text stable.

## Real-speed stress and early-frame inspection

- **Interactive:** if you can render, inspect desktop and phone, including 320 CSS pixel reflow. Exercise the primary journey, failure and recovery; keyboard order and activation; dismissal and focus return; touch targets; long content; contrast; 200 per cent zoom; the reduced-motion path (emulate prefers-reduced-motion: reduce); the pause control; the no-WebGL and no-JS paths; and first paint on a slow connection.
- **Feel stress test:** script it. Hammer each input (dozens of updates in a second), type invalid and boundary values (zero, maximum, empty), sweep the pointer quickly across hover targets, drag the object, resize, switch theme and views, toggle reduced motion. Look for flicker, stale values, controls that move, labels that detach, frozen cameras and console errors. Measure input-to-update time when it matters.

- **Permitted headless graphics:** use the rendering capability the authorised host actually provides. Software rendering may establish captured composition and state, never real-device smoothness. Do not add security/unsafe flags, alter host settings or bypass browser restrictions to force a render; report unavailable capability instead.
- **One-second clip test.** Record the first 3 to 5 seconds after load at 1440 x 900 and 390 x 844 with Playwright's recordVideo, setting recordVideo.size to the viewport (the default shrinks to fit 800 x 800). Time frames from navigation, not from the start of the video. Pull frames at 0.5, 1 and 2 s and view each at about 400 px wide, the way a phone filming a monitor would show it. It passes when one dominant shape reads, something meaningful has moved by the one-second mark, and a stranger could say what kind of site it is. Judge composition, not smoothness: headless Chromium without a GPU renders WebGL in software or not at all.

These are optional showcase-capture checks. A purposeful static page need not move by one second to pass; judge whether its subject, task and hierarchy read at the relevant scale. The clip test does not replace a complete workflow, real viewport inspection or accessibility checks.
