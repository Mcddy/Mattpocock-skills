# Predictive lifecycle

1. Commit sealed test bytes before reviewing labels, feature tuning or model selection. Hashing reads raw bytes but does not parse labels. `seal-test` writes a new seal. It cannot prove that nobody previously saw the data; retain the provenance and prior exposure declaration.
2. Define features with prediction-time evidence and an explicit group/time boundary. The engine enforces numeric features only, forbids target/id/group/time metadata as features, unique row IDs, nonoverlapping entity groups when requested and strict chronological train-before-development-before-test when requested. These are mechanical checks, not automatic leakage discovery.
3. Fit each feature median, mean and population scale on training data. Null means impute with that median; zero remains zero. Entirely missing training columns are refused. Constant columns have scale 1. A mean baseline competes with penalties 0.01, 1 and 10. Ridge solves penalised normal equations with an unpenalised intercept and partial pivoting. Ill-conditioned designs can still require a better numerical adapter.
4. Binary logistic fits use a conservative fixed gradient step with maximum 3000 iterations; output states maximum gradient and convergence. An unconverged candidate is not described as an optimal fit. Comparison uses development log loss (regression: MSE); ties favour the baseline. Training is not refit on development after selection. Binary metrics also retain Brier score and accuracy at the already fixed threshold 0.5. Probabilities are not calibrated by declaration.
5. Export coefficients, preprocessing, feature order and split manifest in JSON. Inference requires all feature keys and finite numbers/null; additional columns are ignored and never become features. IDs remain output lineage. Additional target columns must not be used for inference decisions.
6. The test audit verifies the exact sealed hash and model commitment, locks the seal once, then validates and computes the held-out result. The lock is local workflow control, not tamperproof access control. Do not copy seals to evade it. Failures retain the lock; a newly justified experiment requires a new recorded commitment, not silent retry. Test changes fail hash verification before the lock. Model/data cards should disclose prior exposure, split granularity, target costs, missingness, convergence, actual errors and applicability.

Budget: 64 numeric features, at most 100000 rows per input and an additional binary iteration-work bound. No automatic feature selection, categorical expansion, neural/text pipeline, hyperparameter search, calibrated uncertainty or distribution-shift assurance. Prediction quality follows the actual data and held-out result; no target score is promised.
