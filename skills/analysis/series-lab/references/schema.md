# Series JSON v1

Required: `schema_version:1`, `observations:[{timestamp,value,available_at?}]`, explicit `origins:[ISO timestamps]`. Values are finite numeric or null. Dates are UTC end of day; datetime strings need timezone. Rows must follow the regular grid declared by integer `step_seconds` (default 86400). `horizon` positive integer <=1000, `period` positive integer <=10000. At most 100000 observations and 100000 origin/horizon forecast pairs.

Optional: `evaluation_as_of` (default latest release time), `final_origin` (on-grid no earlier than the last backtest origin), `alpha` in (0,1), `minimum_calibration` integer 2..10000 (default 5), `auxiliary:[{origin,feature,available_at,...}]`, `candidate_split:{origin,training_includes_through}`. Auxiliary content remains metadata; no feature values enter these baseline fits. Per-origin future availability and after-origin training are flagged/rejected as candidate uses, while legitimate baseline forecasts continue.

Output: `metrics` by method, detailed `backtests`, `selected_method`, unscored `final_forecasts`, `availability_violations`, retrospective shift candidates, input_sha256 and limitations. Each backtest contains origin, target, horizon, prediction, fallback, actual, actual_available_at, score_status, interval, calibration_n and interval reason when absent. No missing value is serialised as NaN. Duplicate object keys/NaN/Infinity/malformed dates return controlled exit 2. `--out` refuses an existing file.

Aggregate work limits: 12 MB input, at most 5 million forecast-origin row visits (`rows * origins * 3`) and a conservative 5 million calibration-comparison upper bound (`3 * (origins * horizon)²`). The calibration loop scans previous forecast rows before selecting matching horizons, so both horizon factors matter. These checks precede expensive loops. Larger valid analyses require an explicitly reviewed vectorised/streaming adapter; refusing a resource budget is not evidence about forecasting quality.
