# Corpus v1

Ingest JSON array, max 10000 documents per batch. Each document: nonempty string `id`, literal string `text` (max 2 million characters), optional `entities` list of `{id:string,name:string,attributes:object}`. Other JSON metadata is retained exactly in canonical form, including source URL, publication/access dates, units and original labels. Values are data; duplicate object keys and nonfinite JSON are refused. Repeated document IDs within one batch fail before mutation. Dates are retained, not guessed or reinterpreted.

Merge JSON: `{"id":"review-1","a":"person-a","b":"person-alias","reason":"Reviewed source-specific identity evidence..."}`. Undo JSON: `{"id":"undo-review-1","undo":"review-1","reason":"Contradictory identity evidence..."}`. A reason does not automatically make a decision correct. Supplied entity IDs may themselves be uncertain; label that uncertainty. Avoid credentials or unrelated private people.

Commands: `ingest FILE`; `search "query" --limit 20`; `families --threshold 0.8`; `entities`; `decide FILE`; `resolved`; `export`; `import FILE`. Database path always precedes the command. All JSON result objects are printed to stdout. Use the host's ordinary file tools to save reviewed outputs at new paths. No implicit extraction/network operations.

Snapshot: schema_version 1, `versions` with source_id/revision/raw/record_hash/content_hash/active, and `decisions` with sequence/decision_id/kind/payload. `raw` and `payload` are JSON strings preserving the stored canonical records. Import checks integrity and log structure, not the truth of metadata or reasons. Do not hand-edit committed snapshots; create new ingest or review events instead.

Resource bounds: 20 MB input, 8 million canonical characters per ingestion batch, active corpus at most 10000 records/20 million canonical characters. Near-copy pair work is limited to 20 million shingle visits as well as 2000 records; entity observation comparisons to 2 million. Bounded snapshot import/export permits 20000 historical versions/20 million raw characters and 10000 decision events. A larger retained history requires a reviewed partition/export adapter; no history is deleted to meet a limit. Merge import commitments must be nonempty, cite existing retained source revisions and collectively contain both merged identities. An unrelated cited source cannot legitimise a merge.
