# Incremental source and identity semantics

Each source ID has immutable numbered revisions. Whole-record SHA256 commits canonical JSON containing text plus original metadata/entity observations. A separate UTF-8 raw-text SHA256 identifies exact-content copies. Reingesting an identical record is a no-op. Editing text or metadata creates a new revision and atomically makes the old revision inactive. Search indexes current text only; no cached old tokens survive an update. Export retains every raw version and the append-only identity decision log.

Retrieval is sparse lexical weighted term matching: Unicode NFKC/casefold tokenisation, term frequency 1+log(count), and corpus IDF log((1+N)/(1+document_frequency))+1. Raw text is never replaced by normalised text. The snippet includes literal character offsets into original text and the source version/hash. Offset fallback is 0 when compatibility-normalisation prevents a literal token match. Search relevance is not truth, claim entailment or evidence independence. No vectors or inferred content labels are secretly added.

Exact content hashes group copied text even when URLs/metadata differ. Near-copy candidates use Jaccard similarity over distinct consecutive three-token shingles, default threshold 0.8, requiring at least four distinct shingles on each side. They are pairs, not transitive identity groups: A similar to B and B similar to C does not automatically establish A equivalent to C. Small paraphrases, translations and short records can be missed. Pair scanning is limited to 2000 active documents; partition larger corpora explicitly.

Entity observations are supplied IDs, names and attributes. Candidates arise from normalised-name equality; conflicts on shared attribute keys are retained. Names cannot prove identity. Explicit merge events require two current IDs, a unique decision ID and substantive reason, with all relevant source revisions committed. Current groups replay non-undone, non-stale merges; an explicit undo removes the target merge's contribution while preserving later independent decisions. Source changes invalidate affected old merge decisions. No inferred persistent personal memory is written.

Import validates raw record/content hashes and decision ordering, requires an empty target database and uses one transaction. Malformed state rolls back all data inserts; database schema creation may remain. Retain the original export and compare exported structured snapshots after import. SQLite is a local data file created only at the supplied path, not an installed service. No deletion, arbitrary code, URL fetch, credential access or HTML execution occurs.
