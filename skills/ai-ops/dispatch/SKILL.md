## MODULE 1: Cerberus Intelligence Engine

### The Three-Lens Framework

Every analysis scores all three lenses. Each scored -5 (strongly bearish) to +5 (strongly bullish).

**LENS 1 — MACRO:**
Central bank posture / Economic data cycle / Geopolitical backdrop / Currency interplay / Liquidity conditions / Sector rotation context

**LENS 2 — TECHNICAL:**
Trend structure (HH/HL or breakdown) / Key S/R zones / MA alignment / Momentum (RSI, MACD, ATR) / Volume profile / Pattern recognition / Multi-TF confluence

**LENS 3 — SENTIMENT:**
COT data / Retail vs institutional signals / Options skew and IV / Fear/greed indicators / News sentiment / Analyst consensus and crowding risk

### Asset Weighting Defaults
| Asset | Macro | Technical | Sentiment |
|-------|-------|-----------|-----------|
| Gold/Silver | 40% | 35% | 25% |
| AUD/USD | 35% | 40% | 25% |
| Crude Oil | 35% | 35% | 30% |
| Indices | 30% | 40% | 30% |
| BTC/Crypto | 20% | 45% | 35% |

### Standard Brief Schema
```xml
<cerberus_brief>
  <asset>[Name + ticker]</asset>
  <timestamp>[Date + session]</timestamp>
  <verdict>STRONG_BUY | BUY | HOLD | SELL | STRONG_SELL | WAIT</verdict>
  <conviction>0-100</conviction>
  <macro><score>-5 to +5</score><summary/><key_catalyst/></macro>
  <technical><score/><summary/><entry_zone/><stop_level/><target_1/><target_2/></technical>
  <sentiment><score/><summary/><contrarian_flag>YES|NO</contrarian_flag></sentiment>
  <composite_score>-15 to +15</composite_score>
  <risk_reward/>
  <time_horizon>Intraday | Short-term | Medium-term</time_horizon>
  <key_risk/>
  <execution_note/>
</cerberus_brief>
```

### Pre-Trade Checklist
- [ ] All three lenses scored
- [ ] Composite score threshold met (minimum ±5 for trade recommendation)
- [ ] Stop level defined and logical
- [ ] R:R ratio ≥ 1.5:1
- [ ] Key risk identified
- [ ] No major news catalyst in next 4 hours (unless trading it)

### Calibration Rules
- Composite -4 to +4 → recommend WAIT, never force a direction
- Flag [UNCERTAIN: reason] for any lens with thin data
- Flag [ASSUMPTION: X] for anything unverified
- Rate conviction 0-100 on every verdict

### Rapid Brief (fast assessment)
```
ASSET / VERDICT / CONVICTION
MACRO: [+/-X — one sentence] / TECHNICAL: [+/-X — key level] / SENTIMENT: [+/-X — one sentence]
COMPOSITE: [score] / KEY RISK: [one sentence] / EXECUTE: [specific entry condition]
```

### Cerberus Publication Format
```
1. EXECUTIVE SUMMARY (3 sentences: verdict / key driver / key risk)
2. MACRO LANDSCAPE (2-3 paragraphs)
3. THREE-LENS ANALYSIS (structured per above)
4. ACTIONABLE SETUP (specific levels, conditions, trade structure)
5. RISK REGISTER (top 3 risks: probability × impact)
6. WATCHLIST (2-3 assets for next session)
```
Tone: Direct, institutional, zero filler. Readers are serious operators.

## MODULE 2: Execution Momentum

### Common Failure Modes
1. Analysis paralysis — too much thinking, no first action
2. Scope inflation — project grows before it starts
3. Waiting for perfect — conditions for starting never arrive
4. System design instead of execution — building the framework instead of the thing
5. Momentum loss — good start, then stalls

### 3-Level Breakdown (core protocol)
```
LEVEL 1 — OUTCOME: What does done look like? (Specific. Not "launch Cerberus" — "200 paid subscribers at $X/month by [date]")
LEVEL 2 — MILESTONES: 3-5 major checkpoints that prove progress (observable, achievable in days-weeks)
LEVEL 3 — FIRST ACTIONS: Next 3 actions, each completable in < 2 hours
RULE: Never leave a planning session without Level 3 defined.
```

### Project Kickstart
```
PROJECT / OUTCOME / DEADLINE / STAKES

MILESTONE 1: [X] — by [date]
MILESTONE 2: [X] — by [date]
MILESTONE 3: [X] — by [date]

CURRENT BLOCKERS: [Real vs perceived?]
FIRST ACTION: [Today — < 2 hours]
SECOND ACTION: [This week]
THIRD ACTION: [Before milestone 1]
ACCOUNTABILITY: [How Shaun tracks progress]
```

### Momentum Recovery
```
STALLED PROJECT / LAST ACTION / BLOCKER

DIAGNOSIS:
□ Unclear next action → define the specific next action right now
□ Waiting on external → chase or remove dependency
□ Task too large → break into < 2 hour chunks
□ Lost motivation → reconnect to outcome
□ Scope inflated → cut back to minimum viable
□ Perfectionism → define "good enough" for this stage

FIRST RESTART ACTION: [Hyper-specific, < 2 hours]
```

### MVE Principle
What is the minimum version that: tests the core assumption / delivers real value / can be built in the shortest reasonable timeframe?

- Cerberus MVE: 1 quality issue → 1 paying subscriber → proof of concept
- Prompt MVE: 1 working prompt → 1 sale → proof of commercial value
- Agent MVE: 1 automated workflow that saves X hours → proof of leverage

### Shipping Standards
```
□ Does this solve the stated problem?
□ Good enough for its intended audience at this stage?
□ Worst case if shipped imperfect: [assess]
□ Am I delaying because it needs work, or because I'm afraid?
RULE: Imperfect and shipped > perfect and delayed.
```

## MODULE 3: Second Brain Architect

### Operating System Architecture
```
LAYER 1 — CAPTURE (frictionless inbox): Everything here first. No organising. < 10 seconds.
LAYER 2 — PROCESS (triage, not action): Daily 5-10 mins. Empty inbox. Route or delete.
LAYER 3 — ORGANISE (PARA):
  Projects: Active work with finish line
  Areas: Ongoing responsibilities (trading, Cerberus, AI development)
  Resources: Reference by topic (market data, AI techniques, prompt templates)
  Archive: Searchable but out of view
```

## MODULE 7: Autonomous Writer

### Cerberus Brief Writing Standards
- Direct, institutional, zero filler
- Lead with the verdict, not the background
- Every sentence earns its place
- Readers are serious operators — no hand-holding

### Content Formats

**Market Intelligence Brief:** Executive summary → Three-lens analysis → Actionable setup → Risk register → Watchlist

**Newsletter Issue:** Hook (why this matters now) → Context (the situation) → Analysis (the three-lens picture) → The trade (specific actionable) → Close (what to watch)

**Commercial Content (prompt/product launch):**
Problem → Solution → Proof → What's included → Who it's for → CTA

### Writing Discipline Rules
1. Lead with the conclusion — bury it and you lose them
2. One idea per sentence — complexity per paragraph, simplicity per sentence
3. Cut the first paragraph — 90% of first drafts start too early
4. Active voice — "The brief identifies" not "X is identified by the brief"
5. Specific over general — "$47/month" not "affordable"

## MODULE 8: Workflow Automator

### TRAP Framework (every autonomous workflow)
```
T — TRIGGER: What starts it? (Schedule / Event / Webhook / Threshold / Cascade)
R — RETRIEVE: What context does the agent need? (Live data / Memory / Documents / APIs)
A — ACT: Single-purpose agent job
P — POST: What happens with output? (Save / Send / Notify / Feed next stage)
```

### Pre-Built Workflows (Shaun's domains)

**Daily Cerberus Brief:**
```
TRIGGER: 6am schedule
RETRIEVE: Overnight price action + news feed + sentiment data (Perplexity)
ACT: Three-lens analysis → brief generation → risk flagging (Claude)
POST: Formatted brief → Substack draft or personal inbox
```

**Trade Signal Monitor:**
```
TRIGGER: Price threshold breach (TradingView webhook)
ACT: Rapid three-lens assessment at signal time
POST: Signal brief → Telegram notification with go/no-go recommendation
```

**Research Synthesis Pipeline:**
```
TRIGGER: New URL or document added to inbox folder
ACT: Extract → summarise → tag → connect to knowledge base
POST: Structured note added to system
```

**Prompt Quality Audit:**
```
TRIGGER: New prompt file added to library
ACT: Run against test cases → score against quality rubric → generate improvement notes
POST: Audit report saved alongside prompt file
```

### Automation Stack
| Function | Tool |
|----------|------|
| Scheduling | n8n, APScheduler, cron |
| Notifications | Telegram bot |
| Data ingestion | Perplexity API, RSS feeds |
| Storage | PostgreSQL, Notion API |
| Deployment | Railway, Render |

### Automation Decision Rule
If Shaun is doing something manually more than twice — it should be automated. The question is not whether to automate but which automation stack to use.
