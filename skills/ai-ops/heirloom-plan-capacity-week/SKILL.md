# Schedule against usable hours

Obtain real available windows, hard deadlines, commitments, effort evidence, energy constraints and the outcome the week must produce. Separate calendar availability from deep-work capacity. If availability is unknown, draft a bounded scenario and request the consequential constraint; do not assume every evening is free. Choose ordinary task ordering locally when dependencies permit.

Subtract fixed obligations and maintenance from available hours before allocating new work. Keep active work separate from unattended waiting. Estimate tasks as ranges using similar past tasks when possible; include setup, verification, review and recovery rather than coding alone. Record estimates as estimates, not commitments supported by imaginary productivity.

Define one primary weekly outcome with a checkable artefact and at most a small secondary outcome. Break the primary task into dependency-ordered blocks that fit actual windows. Put the highest-uncertainty proof early so a failure can change the week's plan. A task requiring unavailable client access cannot occupy an executable block; assign an access-resolution or offline rehearsal alternative.

Reserve slack for normal uncertainty and the user's context switching. Do not fill the calendar to its nominal maximum while claiming the result is robust. If required work exceeds capacity, reduce scope, defer lower-value work or propose renegotiating a real deadline. External messages or calendar changes are not automatically authorised by creating a plan.

Use a minimum, target and stretch scope tied to actual evidence. Minimum should leave a useful artefact even when the hard path fails, such as a reproducible failure fixture. Stretch work begins only after target acceptance; it must not steal time from verification. Define stop conditions for rabbit holes and a next-action note at every block end so resumption is cheap.

If a calendar tool is available and authorised, place only agreed blocks; otherwise deliver a local schedule. Midweek review compares actual active time and completed proof with the plan. Carry forward unfinished scope honestly, preserve the original estimate and revise future estimates with the observed overrun rather than rewriting history.

Deliver `capacity_week.md` and `work_blocks.csv` with windows, obligations, available deep-work hours, task dependencies, effort ranges, reserve, minimum/target/stretch acceptance and replanning triggers. Distinguish fixed commitments from tentative blocks.

Acceptance sums blocks and reserve within usable capacity, honours dependencies and leaves a fallback for unavailable access. A negative control with overlapping commitments must be rejected or reconciled. Passing establishes a feasible plan under supplied assumptions, not guaranteed execution or sustained productivity.

Worked situation: a ten-hour week with three hours of study commitments leaves seven. Allocate the risky parser proof and its verification first; defer dashboard polish instead of quietly scheduling a second full project.
